# Автоматизация: аналитик → разработка → реклама

Два вопроса, на которые отвечает этот документ:

1. Может ли аналитик отправлять задачи в Claude Code? — **Да**, через GitHub Issue.
2. Можно ли менять Яндекс.Директ программно? — **Да**, у Директа есть API на запись,
   но включать его стоит осознанно (см. раздел 2).

---

## 1. Аналитик → Claude Code

### Как это работает

Аналитик не «разговаривает» с Claude Code напрямую — прямого канала не существует.
Рабочий путь: **аналитик создаёт issue в репозитории продукта, а Claude Code
реагирует на упоминание `@claude`**.

```
Аналитик находит проблему
   ↓  POST /growth/api/dev-task  (кнопка «В разработку» у сигнала)
GitHub Issue в репозитории продукта, текст начинается с @claude
   ↓  GitHub Actions
Claude Code читает issue, правит код, открывает Pull Request
   ↓
Вы смотрите PR и мержите
```

Что нужно, чтобы это заработало:

**Со стороны аналитика** (переменные окружения):

```
GITHUB_TASK_REPO=belkinboris/AutoPost      # куда ставить задачи
GITHUB_TASK_TOKEN=<PAT с правом issues:write>
```

**Со стороны репозитория продукта** — workflow, реагирующий на `@claude`
(`.github/workflows/claude.yml`):

```yaml
name: Claude Code
on:
  issues:
    types: [opened]
  issue_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.issue.body, '@claude') || contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: read
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

Точные параметры action'а стоит сверить с актуальной документацией — они меняются.

⚠️ Важное ограничение для нашего случая: **Anthropic API недоступен с российских
IP**, но GitHub Actions выполняются на серверах GitHub, не на вашем хостинге,
поэтому здесь это не мешает. Ключ `ANTHROPIC_API_KEY` живёт в секретах репозитория.

### Что именно уходит в задачу

Кнопка «В разработку» у сигнала отправляет заголовок и текст диагноза как есть:
числа из продакшена, а не пересказ. В конце добавляется пометка, что задачу
поставил аналитик и числа — факты. Это важно: Claude Code не должен додумывать
контекст, которого у него нет.

### Про Routines (расписание)

Если хочется, чтобы цикл шёл сам: у Claude Code есть расписания (Routines),
которые могут периодически запускать сессию. Тогда схема такая — аналитик
складывает задачи в issues, а Routine раз в день разбирает накопившееся.
Но осмысленнее оставить триггером именно issue: задача появляется, когда
есть проблема, а не когда наступило время.

### Что остаётся человеку

Правки лендинга и продукта Claude Code делает сам (через PR — вы контролируете
мерж). Реклама остаётся за вами, если не включать раздел 2.

## 2. Яндекс.Директ через API

**Да, Директ можно менять программно.** API v5 умеет не только читать отчёты
(это единственное, что аналитик использует сейчас), но и писать:

| Что можно | Сервис API |
|---|---|
| Создавать/менять/останавливать кампании | `campaigns` |
| Управлять группами и объявлениями | `adgroups`, `ads` |
| Добавлять/удалять ключевые фразы | `keywords` |
| **Минус-фразы** | `keywords`, `adgroups` (negativeKeywords) |
| Ставки и стратегии | `bids`, `bidmodifiers` |
| Дневной бюджет | `campaigns` |

Что нужно: приложение в Яндекс OAuth и токен с правом на запись
(сейчас аналитик использует токен только для Reports Service — на чтение).

### Стоит ли это включать

Технически — да. Практически я бы **не давал аналитику писать в Директ
автоматически**, по крайней мере сейчас, и вот почему:

- ошибка в рекламе стоит денег сразу и необратимо, в отличие от ошибки в коде,
  которую можно откатить;
- выборки у вас пока маленькие (единицы оплат) — на таких данных автоматические
  правки ставок будут шумом, а не оптимизацией;
- принцип аналитика — «одна проверка за раз, остальное не трогаем». Автоматические
  правки рекламы ломают этот принцип: во время проверки продукта реклама должна
  быть заперта.

**Разумный компромисс, который стоит сделать первым:** аналитик готовит
**конкретный список минус-фраз** (он уже умеет находить мусорные запросы через
глубокую проверку Директа) и показывает его кнопкой «скопировать» — вы вставляете
в интерфейс Директа за 30 секунд. Все решения принимаете вы, но думать за вас
не приходится.

Следующий шаг, если захочется автоматизации: разрешить аналитику **только
добавление минус-фраз** (операция почти безопасная, она сужает показы, а не
расширяет траты) и оставить ставки/бюджеты за человеком.

## Что уже готово в платформе

- `POST /growth/api/dev-task` — создать задачу в GitHub (кнопка у каждого сигнала).
- `POST /growth/api/ads/deep-check` — глубокая проверка Директа: какие запросы
  и площадки тратят бюджет без регистраций.
- `GET /growth/api/ads` — расход и результат по источникам в одной таблице.
- `GET /growth/api/history` — история решений: что предлагали, что приняли, чем кончилось.
