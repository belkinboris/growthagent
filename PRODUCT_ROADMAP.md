# Дорожная карта: из внутреннего инструмента в коммерческий продукт

Этот файл — источник правды для непрерывной работы над платформой.
Почасовая рутина читает его, берёт **одну** задачу, делает её целиком
и дописывает результат в журнал внизу.

## Что мы строим

«Аналитик Воронки» — платформа, которая подключается к любому digital-продукту
по HTTP и отвечает владельцу на три вопроса: **что происходит**, **где теряются
люди**, **что делать дальше**. Первый подключённый продукт — АвтоПост
(projectautopost.ru), он же живой полигон. Цель — продукт, который не стыдно
продавать: понятный человеку, который видит его впервые.

Экосистема: «Создатель» ведёт проект на ранних стадиях (идея → лендинг →
проверка спроса), Аналитик подхватывает, когда продукт живой. Платформы
могут слиться или остаться отдельными — архитектура позволяет оба пути
(вся платформа живёт под префиксом `/growth`).

## Принципы, которые нельзя нарушать

Они важнее скорости и важнее красоты. Если задача противоречит принципу —
задача неверна, а не принцип.

1. **Честность данных.** Никогда не показывать выдуманное или экстраполированное
   число как факт. Нет данных — так и писать. Малая выборка — говорить об этом
   словами, а не рисовать уверенный график.
2. **Одна проверка за раз.** Growth Loop меняет одну переменную, фиксирует
   базовый уровень, ждёт выборку, выносит вердикт. Функции, которые позволяют
   менять всё сразу, ломают продукт по смыслу.
3. **Аналитик не принимает решений за владельца.** Он объясняет и предлагает;
   кнопку нажимает человек.
4. **Приватность.** Наружу отдаются агрегаты и анонимные ключи. Ни email,
   ни id пользователей продукта в аналитике быть не должно.
5. **Ядро не знает продуктовой специфики.** Всё, что специфично для АвтоПоста,
   живёт в коннекторах и настройках проекта. Новый клиент подключается без
   правок кода.
6. **Работает из России.** LLM — Yandex (YandexGPT / DeepSeek). Telegram —
   через релей. Никаких зависимостей, недоступных с РФ-хостинга.

### 2026-07-27 20:58 — B1.3: вход и регистрация в интерфейсе, B1 закрыта

подключённый выключенный, а сверху — карточка «Сбор данных по этому
проекту выключен» с честным объяснением: расписание выключено, кнопка

### 2026-07-27 19:59 — B1.2 (и B2): каждый видит только свои проекты

Вторая из трёх частей B1. После B1.1 аккаунты были, но не значили ничего:
любой вошедший читал чужую воронку, деньги и сигналы — фильтрации по
владельцу в запросах не было вовсе.

Что сделано. Четыре помощника в `platform_api.py` и протяжка личности во
все endpoint'ы:

- `_visible_project_ids` — что видно пришедшему. `None` означает «видно всё»
  и бывает только у входа по паролю из окружения: сервер его, ограничивать
  нечем и незачем.
- `_find_project` / `_active_project` — проект, о котором идёт разговор на
  всех экранах, теперь ищется среди своих. Если у аккаунта активного нет,
  а свой проект есть, показываем его: иначе человек видел бы «нет проекта»
  при живом проекте в списке.
- `_owned_project` — проект по номеру с проверкой доступа. Чужой отдаём как
  404, а не 403: 403 подтверждает, что проект с таким номером существует,
  и превращает перебор в разведку.
- `_require_own_project_id` — для объектов, которые ищутся по своему номеру
  (сигнал, рекомендация, эксперимент). Без этого изоляция дырявая: список
  чужого не покажет, а действие по угаданному номеру пройдёт.

Отдельные решения. Кнопка «Проверить сейчас» теперь передаёт номер СВОЕГО
проекта — раньше она запускала цикл по чужому активному. Постановка задачи
разработчику (`/api/dev-task`) закрыта для клиентов: задача уходит в
репозиторий владельца платформы. Название проекта уникально в пределах
владельца, а не всей платформы — иначе первый клиент, назвавший проект
«Магазин», занял бы это слово для всех.

Самое важное — активация. Планировщик собирает ровно один активный проект
(`.first()`), поэтому включение своего проекта вторым клиентом тихо
остановило бы сбор у первого. Молча ломать чужой сбор нельзя, поэтому
платформа отказывает словами (409, «этот проект принадлежит другому
пользователю»). Это честно, но означает, что второй аккаунт продавать
рано — завёл задачу **B7**: планировщик по всем активным проектам.
